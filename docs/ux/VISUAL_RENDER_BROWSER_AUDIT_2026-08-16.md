## 6. Accessibility / human-factors findings

The audit uses WCAG 2.2 as a testable visual/web reference and WCAG2ICT as informative guidance for eventual non-web software. It does not claim formal conformance.

### VRB-A11Y-001 — labeled HTML buttons

**PASS.** No rendered screen contained an HTML `button` with an empty accessible text label.

### VRB-A11Y-002 — M10 pressure-map SVG alternatives

**CORRECTIVE ITEM.** M10 renders three heatmap SVGs generated by `heatSvg()` without an explicit accessible name. The adjacent cards expose BASELINE/OUTCOME/DELTA and metric text visually, but the SVG itself is unlabeled.

Required production/reference correction:

```text
Each meaningful quantitative graphic SHALL have an accessible name/description
or SHALL be explicitly decorative when equivalent quantitative information is
available immediately adjacent in accessible text/table form.
```

For BiomechE maps the preferred implementation is an accessible figure name plus direct access to the underlying numeric metric/ROI/table, because the heatmap is not the quantitative authority.

### VRB-A11Y-003 — viewport tool controls

**CORRECTIVE ITEM.** The mockup uses `.toolbtn` `<div>` elements as visual stand-ins. If those elements become interactive in production they SHALL be real controls with keyboard interaction and programmatic name/role/state; a styled `<div>` is not sufficient.

### VRB-A11Y-004 — focus visibility

**CORRECTIVE ITEM.** The canonical mockup source has no explicit stable `:focus-visible` design rule for buttons/tools. Browser defaults can provide a focus indicator, but the production design system SHALL define and verify a visible focus treatment that remains perceivable in light and dark modes and is not obscured.

### VRB-A11Y-005 — drag alternatives

**PASS AT CONTRACT LEVEL / IMPLEMENTATION REQUIRED.** M05 explicitly presents direct manipulation together with numeric parameters. Production implementation must preserve a non-drag alternative for drag-only adjustments where required by the selected accessibility target.

### VRB-A11Y-006 — state not encoded by color only

**PASS AT VISUAL BASELINE.** Critical visual states use text/icon/shape in addition to color (`PREVIEW`, warning triangle, blocking `!`, confirmed labels, etc.). Production implementation still requires contrast measurement and semantic accessibility-tree verification.

## 7. Human-factors interpretation

The findings are consistent with the frozen interaction doctrine:

```text
perception -> interpretation -> action -> feedback
```

The current reference successfully exposes:

- active case / side / revision context;
- preview versus committed state;
- requested versus realized values;
- blocking versus warning status;
- source/provenance uncertainty;
- measured/result authority distinct from heatmap visualization;
- manufacturing release distinct from artifact generation.

The remaining accessibility items are presentation/control-semantics corrections; they do not require changing the frozen clinical/domain model.
